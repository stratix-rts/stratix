# Claude Code 设计精髓 vs Stratix 现状 — 综合分析与优化建议

> 基于 Claude Code 27 个模块的深度拆解报告，结合 Stratix 源码综合分析

---

## 一、整体架构对比

### Claude Code 架构总览

Claude Code 的核心架构是围绕 **Agent Runtime** 设计的二十七层结构：

```
宿主启动 → 会话运行 → 状态总线 → 工具契约 → 权限编排 → MCP 接入
→ 插件命令折叠 → 技能装配 → Agent 分流 → 任务协同 → 桥接托管
→ Direct Connect 握手 → Direct Connect 流控 → 插件装载治理
→ 命令世界编排 → 远端会话托管 → 启动态内核状态 → 模型请求主循环
→ SDK 数据骨架 → 控制协议定义 → Query 配置快照 → 停点后处理
→ 沙箱执行边界 → provider 适配 → 重试与退避策略 → remote transport
→ token 预算控制 → 结构化回流
```

**五大设计哲学：**
1. **配置/状态/副作用上下文三分法** — 配置快照不变、状态内部流转、上下文提供宿主能力
2. **故障即策略，而非异常即错误** — 故障分类处理、语义化失败、可观测重试
3. **工具即平台契约，而非函数调用** — 工具是完整运行时组件，含验证/授权/调用/呈现/追踪
4. **会话即状态机，而非请求-响应** — 消息流、system prompt、memory、usage、transcript 统进 session
5. **生态即接入层，而非功能堆叠** — 插件和技能是宿主能力的一部分

### Stratix 当前架构

Stratix 采用分层架构：

```
Vue/Phaser UI 层
    ↓
stratix-rts (RTS 游戏场景，Phaser 3)
    ↓
stratix-gateway (Express API + WebSocket)
    ↓
ExecutorFactory (direct/openclaw/stratix 三种执行器)
    ↓
LLM Providers / OpenClaw
```

**现状问题：**
- Zone 系统（OKR）定位为数据容器，缺少完整的 Zone Runtime 概念
- Agent 执行缺少会话级状态抽象（ToolUseLoop 是单次循环，非跨 turn 会话）
- 事件总线分散（StratixEventBus / GatewayEventBus / RTSEventBus），缺少统一状态内核
- 工具能力缺少显式元数据描述（isReadOnly/isDestructive/isConcurrencySafe）
- 重试策略简单（指数退避），缺少故障分类和语义化失败处理

### 3.1 [P0-1] Tool 能力契约层

### 3.2 [P0-2] 会话级状态机

**Claude Code 怎么做：**

```typescript
    // 3. 进入 query loop
    // 4. 产出 SDKMessage 流
  }
}
```

**Stratix 现状：**

`ToolUseLoop.ts` 是单次循环，无跨 turn 状态：
```typescript
class ToolUseLoop {
  async execute(
    initialMessages: ChatMessage[],
    tools: ToolDefinition[],
    context: ExecutionContext
  ): Promise<ToolUseLoopResult> {
    // 单次 LLM → 工具 → LLM → ... 循环
```

```typescript

  // 无会话级状态追踪

}
```

**优化方案：**

在 `stratix-core/` 下新增 `SessionRuntime.ts`：

```typescript
// stratix-core/SessionRuntime.ts

export interface SessionContext {
  sessionId: string;
  agentId: string;
  messages: ChatMessage[];           // 跨 turn 消息历史
  usage: {
    promptTokens: number;
    completionTokens: number;
    totalTokens: number;
  };
  permissionDenials: PermissionDenialRecord[];
  fileCache: Map<string, FileCacheEntry>;
  discoveredSkills: Set<string>;
  createdAt: number;
  lastActiveAt: number;
}

export class SessionRuntime {
  private sessions: Map<string, SessionContext> = new Map();

  getOrCreateSession(agentId: string, sessionId?: string): SessionContext {
    const id = sessionId || `session-${Date.now()}-${Math.random().toString(36).slice(2)}`;
    if (!this.sessions.has(id)) {
      this.sessions.set(id, this.createSession(id, agentId));
    }
    return this.sessions.get(id)!;
  }

  addMessage(sessionId: string, message: ChatMessage): void {
    const session = this.sessions.get(sessionId);
    if (session) {
      session.messages.push(message);
      session.lastActiveAt = Date.now();
    }
  }

  recordUsage(sessionId: string, usage: Usage): void {
    const session = this.sessions.get(sessionId);
    if (session) {
      session.usage.promptTokens += usage.promptTokens;
      session.usage.completionTokens += usage.completionTokens;
      session.usage.totalTokens += usage.totalTokens;
    }
  }

  recordPermissionDenial(sessionId: string, denial: PermissionDenialRecord): void {
    const session = this.sessions.get(sessionId);
    if (session) {
      session.permissionDenials.push(denial);
    }
  }

  // 先写 transcript 再跑 API
  async executeWithTranscript(
    sessionId: string,
    messages: ChatMessage[],
    execute: () => Promise<LLMResponse>
  ): Promise<LLMResponse> {
    // 1. 写 transcript（持久化）
    this.persistTranscript(sessionId);
    // 2. 执行
    const result = await execute();
    // 3. 更新 usage
    if (result.usage) {
      this.recordUsage(sessionId, result.usage);
    }
    return result;
  }
}
```

**涉及文件：**
- 新增：`src/stratix-core/SessionRuntime.ts`
- 修改：`src/stratix-agent/EnhancedStratixAgent.ts`（使用 SessionRuntime）
- 修改：`src/stratix-agent/core/ToolUseLoop.ts`（接受 SessionContext）

**预期收益：**
- 跨 turn 消息历史可追踪，支持对话续接
- usage 统计精确到会话级别
- 权限拒绝记录可查询（用于权限系统优化）
- transcript 持久化防止消息丢失

### 3.3 [P0-3] 权限决策编排器

**Claude Code 怎么做：**

`useCanUseTool.tsx` 是异步竞争决策：
```typescript
const decisionPromise = new Promise<PermissionDecision<Input>>(resolve => {
  const sources = [
    hasPermissionsToUseTool(),      // 本地规则
    tryClassifier(),                 // classifier
    runHooks(),                     // hooks
    waitForUserDialog(),            // UI 点击
    waitForBridgeReply(),           // bridge 回复
    waitForSwarmLeaderReply(),      // swarm leader 回复
  ];
  const resolveOnce = createResolveOnce(resolve);
  for (const source of sources) {
    source.then(result => {
      if (!resolveOnce.isResolved()) {
        resolveOnce.resolve(mapToPermissionDecision(result));
      }
    });
  }
});
```

三态返回值：
```typescript
type PermissionDecision<Input> =
  | { type: 'allow'; input: Input; ... }
  | { type: 'deny'; reason: string; ... }
  | { type: 'ask'; dialog: DialogConfig; ... };
```

**Stratix 现状：**

命令执行无权限审查，直接调用：
```typescript
// OpenClawExecutor.execute()
const response = await adapter.execute(action);
```

无 `checkPermissions` 调用，无 ask 流程，无 classifier。

**优化方案：**

在 `stratix-core/` 下新增 `PermissionOrchestrator.ts`：

```typescript
// stratix-core/PermissionOrchestrator.ts

import { CapabilityDescriptor, PermissionDecision } from './types/capability';

export interface PermissionContext {
  sessionId: string;
  agentId: string;
  zoneId?: string;
  projectId?: string;
  userId?: string;
}

export class PermissionOrchestrator {
  private hooks: PermissionHook[] = [];
  private classifiers: PermissionClassifier[] = [];

  async decide(
    skill: CapabilityDescriptor,
    input: any,
    ctx: PermissionContext
  ): Promise<PermissionDecision> {
    const decisionPromise = new Promise<PermissionDecision>(resolve => {
      const sources: Promise<PermissionDecision>[] = [];

      // 1. 本地规则检查
      sources.push(this.checkLocalRules(skill, input, ctx));

      // 2. Classifier 预测
      sources.push(this.runClassifiers(skill, input, ctx));

      // 3. Hooks
      sources.push(this.runHooks(skill, input, ctx));

      // 4. UI 等待（ask 态）
      sources.push(this.waitForUserDialog(skill, input, ctx));

      const resolveOnce = createResolveOnce(resolve);
      for (const source of sources) {
        source.then(result => {
          if (!resolveOnce.isResolved()) {
            resolveOnce.resolve(result);
          }
        });
      }
    });

    return decisionPromise;
  }

  // speculative auto-approve：低风险操作等 2 秒 classifier 结果
  async speculativeCheck(
    skill: CapabilityDescriptor,
    input: any,
    ctx: PermissionContext
  ): Promise<PermissionDecision> {
    if (!skill.isReadOnly) {
      return this.decide(skill, input, ctx);
    }

    const classifierResult = this.runClassifiers(skill, input, ctx);
    const timeout = new Promise<PermissionDecision>((resolve) =>
      setTimeout(() => resolve({ type: 'allow', input }), 2000)
    );

    return Promise.race([classifierResult, timeout]);
  }
}
```

集成到 ToolUseLoop：
```typescript
// ToolUseLoop.execute() 中调用
const permissionDecision = await permissionOrchestrator.speculativeCheck(
  skill, input, ctx
);
if (permissionDecision.type === 'deny') {
  return { success: false, error: `Permission denied: ${permissionDecision.reason}` };
}
if (permissionDecision.type === 'ask') {
  // 等待用户审批
  await permissionOrchestrator.waitForApproval(permissionDecision.dialog);
}
```

**涉及文件：**
- 新增：`src/stratix-core/PermissionOrchestrator.ts`
- 修改：`src/stratix-agent/core/ToolUseLoop.ts`
- 修改：`src/stratix-core/types/capability.ts`

**预期收益：**
- 权限决策可追溯、可配置
- 低风险操作自动放行，高风险操作用户审批
- deny 状态带 memoryCorrectionHint 供模型纠偏

### 3.4 [P0-4] 故障策略引擎

**Claude Code 怎么做：**

`withRetry.ts` 是完整的故障策略引擎：
```typescript
async function* withRetry(request: APIRequest): AsyncGenerator<SystemAPIErrorMessage, T> {
  // 故障分型：
  // - 普通 retry / exponential backoff
  // - 429 / 529 的差异化处理
  // - foreground / background / unattended 三种来源语义
  // - fast mode cooldown 与回退
  // - persistent unattended retry
  // - stale keep-alive connection 失效
  // - OAuth / AWS / GCP 认证缓存刷新
  // - max_tokens 上下文溢出的自动调参
  // - fallback model 触发
}
```

**Stratix 现状：**

`RetryStrategy.ts` 只有简单指数退避：
```typescript
export const DEFAULT_RETRY_CONFIG: RetryConfig = {
  maxRetries: 3,
  initialDelayMs: 1000,
  maxDelayMs: 10000,
  backoffMultiplier: 2,
  retryableErrors: [
    ErrorCode.LLM_CONNECTION_FAILED,

    ErrorCode.LLM_RATE_LIMITED,

```

无故障分类、无差异化处理、无 fallback chain。

**优化方案：**

重写 `RetryStrategy.ts`：

```typescript
// stratix-core/RetryStrategy.ts

export enum FailureType {
  TRANSIENT = 'TRANSIENT',           // 临时故障，可重试
  RATE_LIMITED = 'RATE_LIMITED',     // 限流，差异化退避
  AUTH_EXPIRED = 'AUTH_EXPIRED',      // 认证失效，需刷新
  CONTEXT_OVERFLOW = 'CONTEXT_OVERFLOW', // 上下文溢出，需调参
  FATAL = 'FATAL',                   // 致命错误，不可重试
  UNKNOWN = 'UNKNOWN',
}

export interface RetryPolicy {
  maxRetries: number;
  initialDelayMs: number;
  maxDelayMs: number;
  backoffMultiplier: number;
  failureTypes: {
    [key in FailureType]?: {
      maxRetries?: number;
      delayMs?: number;
      shouldRetry: boolean;
      fallbackModel?: string;
    };
  };
}

export class RetryEngine {
  constructor(private policy: RetryPolicy) {}

  async execute<T>(
    fn: () => Promise<T>,
    context: { source: 'foreground' | 'background' | 'unattended' }
  ): Promise<{ result?: T; error?: StratixAgentError; failureType?: FailureType }> {
    let lastError: Error | undefined;

    for (let attempt = 0; attempt <= this.policy.maxRetries; attempt++) {
      try {
        const result = await fn();

        // 成功：检查是否需要记录失败尝试
        if (lastError && attempt > 0) {
          this.onRetrySuccess(attempt);
        }
        return { result };

      } catch (error) {
        lastError = error as Error;
        const failureType = this.classifyFailure(error);

        const failureConfig = this.policy.failureTypes[failureType];
        if (!failureConfig?.shouldRetry || attempt >= (failureConfig.maxRetries ?? this.policy.maxRetries)) {
          return {
            error: this.wrapError(error, failureType),
            failureType,
          };
        }

        // 差异化退避
        const delay = failureConfig.delayMs
          ?? Math.min(this.policy.initialDelayMs * Math.pow(this.policy.backoffMultiplier, attempt), this.policy.maxDelayMs);

        // foreground 529 可重试，background 529 尽快失败
        if (failureType === FailureType.RATE_LIMITED && context.source === 'background') {
          return { error: this.wrapError(error, failureType), failureType };
        }

        await this.sleep(delay);
      }
    }

    return { error: this.wrapError(lastError!, FailureType.UNKNOWN), failureType: FailureType.UNKNOWN };
  }

  private classifyFailure(error: any): FailureType {
    if (error?.code === 429) return FailureType.RATE_LIMITED;
    if (error?.code === 529) return FailureType.RATE_LIMITED;
    if (error?.message?.includes('401') || error?.message?.includes('auth')) return FailureType.AUTH_EXPIRED;
    if (error?.message?.includes('max_tokens') || error?.message?.includes('context')) return FailureType.CONTEXT_OVERFLOW;
    if (error instanceof StratixAgentError && error.code === ErrorCode.INVALID_CONFIG) return FailureType.FATAL;
    return FailureType.TRANSIENT;
  }
}
```

**涉及文件：**
- 修改：`src/stratix-core/errors.ts`（新增 FailureType）
- 重写：`src/stratix-agent/core/RetryStrategy.ts`
- 修改：`src/stratix-core/executor/OpenClawExecutor.ts`（使用 RetryEngine）
- 修改：`src/stratix-core/executor/StratixAgentExecutor.ts`（使用 RetryEngine）

**预期收益：**
- 429/529 差异化处理（foreground 等，background 快速失败）
- 认证失效自动刷新 token
- 上下文溢出自动调参（减少 maxTokens）
- fallback model 链（primary 不可用时切换）

```typescript
// stratix-core/AgentRouter.ts

export interface AgentRouterConfig {
  agentId: string;
  task: AgentTask;
  context: {
    availableMcpServers: string[];
    currentZoneId?: string;
    permissionMode: 'auto' | 'ask' | 'deny';
    userId?: string;
  };
}

export class AgentRouter {
  async route(config: AgentRouterConfig): Promise<AgentExecutionPlan> {
    const { agentId, task, context } = config;

    // 1. 获取可用工具池（基于 MCP 连接状态）
    const availableTools = await this.getAvailableTools(context.availableMcpServers);

    // 2. 过滤可用 agent（基于权限）
    const agentConfig = await this.getAgentConfig(agentId);
    const isAllowed = this.checkPermission(agentConfig, task, context.permissionMode);
    if (!isAllowed) throw new AgentPermissionDeniedError(agentId);

    // 3. 计算执行形态
    const executionMode = this.computeExecutionMode(task, context);

    // 4. 路由到执行器
    const executor = ExecutorFactory.getInstance().getExecutor(agentConfig);

    return {
      executor,
      executionMode,
      availableTools,
      task,
    };
  }

  private computeExecutionMode(task: AgentTask, ctx: AgentRouterContext): ExecutionMode {
    const shouldRunAsync =
      task.background ||
      ctx.currentZoneId !== undefined || // Zone 任务默认后台
      task.priority === 'low';

    const isolation = task.isolation || 'none';

    return { shouldRunAsync, isolation };
  }
}
```

```typescript
      this.extractMemoriesHook,       // 提取记忆

        const result = await hook.execute(context);

      } catch (error) {
        results.push({ success: false, error });

    const ctx_data = zoneRepository.getZoneContext(ctx.zoneId);
    // 计算完成度，更新 prompt 或其他 OKR 相关字段
    return { success: true };
  }
}
```

## 五、总结

Claude Code 的核心启示：**Agent 产品 = 模型能力 + 宿主运行时 + 协议契约 + 状态管理 + 故障策略 + 接入生态**

Stratix 当前定位：**数据容器 + API 服务 + Phaser 可视化**，缺少完整的 Agent Runtime。

**核心差距：**
1. Tool 能力缺少元数据描述（权限/UI 渲染/可观测性）
2. 会话状态散落，跨 turn 无追踪
3. 权限决策无编排，命令执行无审查
4. 故障处理简单，无策略引擎
5. 状态内核缺失，三个事件总线各自为政

**关键行动项（按优先级）：**
| 优先级 | 行动 | 涉及文件 | 预期收益 |
|--------|------|----------|----------|
| P0-1 | Tool 能力契约层 | 新增 capability.ts | 权限自动决策 |
| P0-2 | 会话级状态机 | 新增 SessionRuntime.ts | 跨 turn 追踪 |
| P0-3 | 权限决策编排器 | 新增 PermissionOrchestrator.ts | 统一权限审查 |
| P0-4 | 故障策略引擎 | 重写 RetryStrategy.ts | 韧性提升 |
| P0-5 | 统一状态内核 | 新增 AppStateStore.ts | 状态集中管理 |

**终极目标：让 Stratix 成为 Phaser RTS 界面上的 Agent Runtime，而不只是调模型的终端程序。**
