### 核心差距分析

| 维度 | Claude Code | Stratix | 差距 |
|------|-------------|---------|------|
| 状态管理 | AppStateStore 统一状态面，跨 UI/runtime/MCP/Agent | 状态分散在各个服务中 | 显著 |
| 权限系统 | useCanUseTool 完整三态决策，含 classifier/hook/远端审批 | 无正式权限决策层 | 严重 |
| 会话运行时 | QueryEngine 统一会话管理，含 transcript/usage/memory | EnhancedStratixAgent 较原始 | 显著 |
| 工具契约 | Tool.ts 五位一体（验证/授权/调用/呈现/追踪） | ToolUseLoop 较简单 | 显著 |
| 容错策略 | withRetry 集中治理，含故障分型/退避/fallback | 无统一重试策略 | 严重 |
| MCP 接入 | 完整协议映射、认证、连接韧性 | 基础连接管理 | 中等 |
| 命令编排 | commands.ts 统一装配多来源命令 | 命令散落在各服务 | 中等 |
| SDK 协议 | coreSchemas.ts Zod 定义，跨边界数据可校验 | TypeScript interface 为主 | 中等 |

### 4.1 [P0] 建立统一状态层 StratixStateStore

**Claude Code 怎么做**：
```typescript
// AppStateStore.ts - 运行时状态骨架
interface AppState {
  tasks: TaskState;
  mcp: MCPState;
  plugins: PluginState;
  notifications: Notification[];
  // ...按领域分仓
}
const store = createStore(defaultState);
// 统一 accessor，selector 模式防止重渲染
```

**Stratix 现状**：
- `StratixEventBus` 只有事件广播，无状态存储
- `GatewayEventBus` 基于 EventEmitter，状态分散
- 各模块直接引用单例或使用 props drilling

**优化方案**：
```typescript
// src/stratix-core/state/StratixStateStore.ts
interface StratixState {
  agents: Map<string, AgentState>;
  zones: Map<string, ZoneState>;
  sessions: Map<string, SessionState>;
  ui: UIState;
  mcp: MCPState;
}

class StratixStateStore {
  private store: Map<keyof StratixState, any>;
  private subscribers: Map<string, Set<() => void>>;

  get<K extends keyof StratixState>(key: K): StratixState[K];
  set<K extends keyof StratixState>(key: K, value: StratixState[K]): void;
  subscribe<K extends keyof StratixState>(key: K, handler: () => void): () => void;
}
```

**涉及文件**：
- 新建：`src/stratix-core/state/StratixStateStore.ts`
- 新建：`src/stratix-core/state/types.ts`
- 修改：`src/stratix-rts/StratixRTSGameScene.ts`（接入状态层）
- 修改：`src/stratix-gateway/ZoneService.ts`（接入状态层）

**预期收益**：
- 消除隐式状态依赖
- UI 和 runtime 共用同一状态源
- 便于调试和持久化

### 4.2 [P0] 建立权限决策编排器 PermissionOrchestrator

**Claude Code 怎么做**：
```typescript
// useCanUseTool.tsx - 权限三态决策
type PermissionDecision =
  | { type: 'allow'; input: Input }
  | { type: 'deny'; reason: string }
  | { type: 'ask'; dialog: DialogConfig };

// 异步决策竞赛，多来源竞争
const decisionPromise = new Promise(resolve => {
  const sources = [
    hasPermissionsToUseTool(),   // 本地规则
    tryClassifier(),              // classifier
    runHooks(),                   // hooks
    waitForUserDialog(),          // UI 点击
  ];
  createResolveOnce(resolve); // 只 resolve 一次
});
```

**Stratix 现状**：
- ZoneService 的权限检查散落在各方法中
- 无正式的 allow/deny/ask 三态
- 无 classifier/hook/远端审批机制

**优化方案**：
```typescript
// src/stratix-core/permission/PermissionOrchestrator.ts
interface PermissionContext {
  zoneId?: string;
  agentId: string;
  action: string;
  resource?: string;
  input?: any;
}

type PermissionDecision =
  | { type: 'allow'; decisionReason?: string }
  | { type: 'deny'; reason: string; correctionHint?: string }
  | { type: 'ask'; requiresUserConfirmation: boolean };

class PermissionOrchestrator {
  async decide(ctx: PermissionContext): Promise<PermissionDecision> {
    // 1. 检查 Zone 规则
    const zoneRule = await this.checkZoneRules(ctx);
    if (zoneRule) return zoneRule;

    // 2. 检查 classifier（低风险操作自动放行）
    const classifierResult = await this.runClassifier(ctx);
    if (classifierResult.confident) return classifierResult;

    // 3. 检查 hook
    const hookResult = await this.runPermissionHooks(ctx);
    if (hookResult.resolved) return hookResult;

    // 4. 回落到用户对话框
    return this.showUserDialog(ctx);
  }
}
```

**涉及文件**：
- 新建：`src/stratix-core/permission/PermissionOrchestrator.ts`
- 新建：`src/stratix-core/permission/types.ts`
- 修改：`src/stratix-gateway/ZoneService.ts`（接入权限检查）

**预期收益**：
- Zone 操作有正式权限语义
- 低风险操作自动放行，提升 UX
- 支持远端审批、hook 扩展

### 4.8 [P1] 建立 SDK Schema 底板

**Claude Code 怎么做**：

**Stratix 现状**：
- `stratix-protocol.ts` 只有 TypeScript interface

**优化方案**：
```typescript
// src/stratix-core/schemas/index.ts
import { z } from 'zod';

// Zone Schema
export const ZoneSchema = z.object({
  id: z.string(),
  title: z.string(),
  prompt: z.string().optional(),
  members: z.array(z.string()).default([]),
  status: z.enum(['active', 'archived', 'deleted']).default('active'),
});

// Message Schema
export const MessageSchema = z.object({
  id: z.string(),
  role: z.enum(['user', 'assistant', 'system', 'agent']),
  content: z.string(),
  timestamp: z.number(),
});

// Agent State Schema
export const AgentStateSchema = z.object({
  agentId: z.string(),
  status: z.enum(['idle', 'busy', 'error', 'offline']),
  currentZone: z.string().optional(),
  lastActiveAt: z.number().optional(),
});

// 跨边界事件 Schema
export const ZoneEventSchema = z.object({
  eventType: z.string(),
  zoneId: z.string(),
  projectId: z.string(),
  data: z.record(z.any()).optional(),
  timestamp: z.number(),
});
```

### 4.9 [P1] 建立 Token 预算控制 BudgetController

**Claude Code 怎么做**：
```typescript
// tokenBudget.ts - 边际收益判断
interface TokenBudgetDecision {
  action: 'continue' | 'stop';
  nudgeMessage?: string;
  continuationCount: number;
  pct: number;
  budget: number;
  completionEvent?: string;
}

// 边际收益判断
const isDiminishingReturns = tokenChange < DIMINISHING_THRESHOLD;
const shouldContinue = pct < COMPLETION_THRESHOLD && !isDiminishingReturns;
```

**Stratix 现状**：
- Agent 执行循环无停止决策
- 依赖用户中断或超时
- 无边际收益概念

**优化方案**：
```typescript
// src/stratix-agent/runtime/BudgetController.ts
interface BudgetConfig {
  maxTokens: number;
  completionThreshold: number;  // 默认 0.9
  diminishingThreshold: number;  // 默认 500
  maxContinuations: number;     // 默认 10
}

interface BudgetDecision {
  action: 'continue' | 'stop';
  reason: string;
  continuationCount: number;
  pctUsed: number;
  remainingBudget: number;
  nudgeMessage?: string;
}

class BudgetController {
  constructor(private config: BudgetConfig) {}

  evaluate(usage: TokenUsage, continuationCount: number): BudgetDecision {
    const pct = usage.totalTokens / this.config.maxTokens;
    const tokenChange = usage.totalTokens - this.lastUsage.totalTokens;

    // 判断是否收益递减
    const isDiminishing = tokenChange < this.config.diminishingThreshold;

    // 判断是否超过阈值
    const isOverThreshold = pct >= this.config.completionThreshold;

    if (isOverThreshold || isDiminishing) {
      return {
        action: 'stop',
        reason: isOverThreshold ? 'budget_exhausted' : 'diminishing_returns',
        continuationCount,
        pctUsed: pct,
        remainingBudget: this.config.maxTokens - usage.totalTokens,
        nudgeMessage: this.generateNudgeMessage(pct, isDiminishing),
      };
    }

    return { action: 'continue', reason: 'ok', continuationCount, pctUsed: pct, remainingBudget: this.config.maxTokens - usage.totalTokens };
  }
}
```

**涉及文件**：
- 新建：`src/stratix-agent/runtime/BudgetController.ts`
- 修改：`src/stratix-agent/EnhancedStratixAgent.ts`（接入预算控制）

**预期收益**：
- Agent 知道何时该停
- 避免无效 token 消耗
- 可配置收敛策略

```typescript
class StratixBootstrapState {
```

## 六、核心结论与行动项

### 核心结论

1. **Stratix 的定位应该是"Phaser RTS 界面上的 Agent Runtime"**，而不只是调模型的终端程序

2. **当前最大差距是缺少中心化状态层**。Claude Code 的 AppStateStore 是整个架构的骨架，Stratix 需要类似的设计才能支撑复杂多 Agent 协作

3. **权限系统是当前缺失最严重的功能**。Zone 作为 OKR 载体，需要完整的权限决策机制（allow/deny/ask 三态）

4. **容错策略需要集中治理**。散落在各处的 LLM 调用需要统一收口到 RetryPolicyEngine

5. **Session Runtime 是 Agent 产品化的关键**。QueryEngine 证明了 Agent 的本质是 session runtime，Stratix 需要建立类似的架构

|--------|--------|---------|------|

### 一句话总结

> Claude Code 证明了：**Agent 产品 = 模型能力 + 宿主运行时 + 协议契约 + 状态管理 + 故障策略 + 接入生态**。Stratix 的目标应该是成为 Phaser RTS 界面上的 Agent Runtime，当前的首要任务是补齐状态层、权限系统、容错策略和 Session Runtime 这四个核心基础设施。
