## 3. 行为漂移清单（矩阵目标 vs 现状 —— 本单只记账，不改代码）

> 判定口径：**矩阵 §2.2 的「目标」列 + §3 的消解设计**为准；现状以 HEAD `1d513b4` 的实现为准（实测自本单新写的回归套件）。

### 漂移① P3×O2 · 双击空白地面 = **回全景** —— 未落地

| 项 | 内容 |
|---|---|
| 矩阵目标 | §2.2 `P3 × O2`：目标 = **回全景**（等价 ESC）；§3 C-02：跟随镜头的去处改绑到「双击空白地面」 |
| 现状 | 双击空白地面 ⇒ 两次都走「点空地 = 清空选择」（`selection.box` 空集），**镜头完全不动**（无补间、无 `view.apply`） |
| 原因 | 空白地面起手 ⇒ `dragMode='box'`（`BattlefieldScene.ts:974`），`pointerup` 走 box 分支，**从不进 click 分支** ⇒ 双击判定（`resolveCanvasClick`）根本没被调用 |
| 影响 | 跟随镜头没有「去处」；`toggleFollow` 仍可用但入口只剩双击单位（见漂移③） |
| 记账位置 | world 套件 `漂移①` |

### 漂移② P8 · ESC **不再回全景** —— world 半边未落地（C-01 未消解）

| 项 | 内容 |
|---|---|
| 矩阵目标 | §2.2 `P8`：目标 = **ESC = 关闭最上层浮层 / 取消选择，不再回全景**（镜头归位改绑 P3×O2）；§4 IX-04 验收①：「按一次 ESC ⇒ 只清选择，镜头**不动**」 |
| 现状 | world 侧 ESC 仍走「回全景」（`BattlefieldScene.ts:1356` `onEscape` → `tweenCameraTo(overviewPose(...))`）；HUD 侧 ESC 仍是「取消选择」（`shortcut-catalog.ts`）⇒ **一次 ESC 同时「镜头归位」+「清空选择」** —— 正是 §3 C-01 描述的撞车后果 |
| 备注 | task_217（IX-04）的 requirements 写的是「仪式播放 > 聊天框焦点 > **镜头归位**优先级链落地」⇒ 该单**刻意**把镜头归位留在链尾，与设计文档 §2.2/§4 IX-04 验收① 存在口径出入；本单按设计文档口径记账，**不动代码** |
| 记账位置 | world 套件 `漂移②`（+ 既有 `src/world/__tests__/keyboard-priority.test.ts` 的链尾断言同现状） |

### 漂移③ P3×O1 · 双击单位 = **只**开聊天框 —— 现状顺带进入跟随镜头

| 项 | 内容 |
|---|---|
| 矩阵目标 | §0 D3 + §3 C-02：「双击 agent = 开单独聊天框」；「跟随镜头**让位**，改绑『双击空白地面 = 回全景』」；仅保留「跟随态下双击同一单位仍解除跟随」 |
| 现状 | 双击单位 ⇒ `bridge.unitChatOpen()` **且** `toggleFollow(hit.id)`（`BattlefieldScene.ts:1071-1074`）⇒ 未跟随时**顺带把镜头拉到该单位**（`tweenCameraTo` 被调 1 次） |
| 备注 | 代码注释写明是刻意保留 task_079 的「跟随可用」（`BattlefieldScene.ts:1072`），与设计 D3「让位」有出入 ⇒ 记账 |
| 记账位置 | world 套件 `漂移③` |

### 漂移④ P10×O2 · Shift + 点空地 —— 矩阵「现状列」与实现不符

| 项 | 内容 |
|---|---|
| 矩阵口径 | §2.2 `P10 × O2` 的**现状列**写：「点空地 = 清空（**Shift+点空地也清空**）」；目标列 = 「不变（记录为已知口径）」 |
| 现状 | Shift + 点空地 ⇒ `selection.box(unitIds: [], additive: true)` ⇒ core 走 `add` + 空集 ⇒ **选择集原样不动（不清空）** |
| 结论 | 矩阵「现状列」的描述与实现不符（实现侧行为 = 不清空）；目标列「不变」本身成立（现状 = 目标 = 不清空） |
| 记账位置 | world 套件 `漂移④` + core 套件 `漂移④（core 侧）` |

### 漂移小结

| # | 矩阵行 | 严重度 | 一句话 |
|---|---|---|---|
| ① | P3×O2 | 中 | 双击空白不回全景（跟随镜头没有去处） |
| ② | P8 | **高** | ESC 仍同时「镜头归位 + 清空选择」（C-01 未消解，一次 ESC 两个动作） |
| ③ | P3×O1 | 中 | 双击单位顺带进入跟随镜头（与 D3「跟随让位」有出入） |
| ④ | P10×O2 | 低 | 矩阵「现状列」描述与实现不符（Shift+点空地不清空） |

## 5. 后续建议（不在本单范围）

1. **漂移② 优先**：ESC 收权是设计里唯一明确「一条键击一个动作」的裁决 —— 建议独立单处理
   （world 侧移除 `keydown-ESC` 的回全景分支，同时把「回全景」绑到 P3×O2），**且必须先落漂移①**
   （否则镜头归位会彻底失去入口）。
2. **漂移① + ③ 一起处理**：双击空白回全景 ⇒ 双击单位不再顺带跟随 —— 这两条是同一次手势的两半，
   分开改会留下「双击单位既开框又跟随」的中间态。
3. **漂移④**：改矩阵的「现状列」还是改实现，取决于产品意图（Shift+点空地要不要清选）—— 需用户裁决。
