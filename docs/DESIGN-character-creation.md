## 0. 用户原话（问题锚点）

> 新建角色面板，在没有任何角色的情况下，没法新建角色，这个流程交互有问题

## 1. 实证断点清单（5 处，全部亲自复现/代码定位）

### CC-B1 🔴 角色中心 0 角色 = 纯死胡同（用户撞上的主断点）
- `src/hud/screens/character-screen.ts:1439`：空态只有文字「尚无角色档案：建好角色后，这里会显示全部角色」——**没有任何创建入口**；全屏动作清单全是编辑向（改名/人设/形象/排行，见 :880-1455 各 data-action）。
- `src/hud/screens/main-screen.ts:36-37`：角色中心是**子屏替换**（自带 topbar+返回钮，主屏 topbar 整个不在场）⇒ 顶栏「＋角色」（main-screen.ts:682）在角色中心**也不可用**。
- 结果：用户站在角色中心，眼前写着"建好角色后会显示"，但没有任何按钮能建。**这就是"新建角色面板，没法新建角色"的字面现场。**

### CC-B2 🔴 向导挂不起时，兜底恰好跳进 B1 死胡同
- `src/app/main/main-entry.ts:1260-1268`：`openCharacterWizard()` → `reopen({force:true})` → `onboarding-host.ts:155-159` 要求 `resolveBindableKinds(lastState).length > 0`（探到已装可建档 agent 才挂）→ 挂不起就 `ui.navigate('character')` —— **退到 B1 的死胡同**。
- 触发场景：agent 扫描未完成/零结果时点击任何「新建角色」入口（空态 CTA / 顶栏 / ⌘K）。

### CC-B3 🟠 人设步「下一步」亮着但点了没反应（静默吞点击）
- 实测：向导走到人设步，主按钮 `disabled:false`（`onboarding-screen.ts:2021` 的 `stepBlockReason()` 只挡 identity/confirm，:2009 返回 null），点击 → `next():669` → `validatePersonaStep():1046` 校验失败 **return 原地**，只在题目旁标「这一题还没选」。
- 用户视角：按钮是亮的、点了三次没反应、不知道该干嘛——与 B1 叠加就是「没法新建角色」。
- 讽刺点：空人设本身是**合法**的（建档套默认模板，personaSectionSummary :2001「（空：建档时套用默认模板）」），但问卷却被强制答完。

### CC-B4 🟡 扫描步 0 结果 = 无路可走
- `onboarding-screen.ts:1330`：空态文案「还没探测到本机 agent：确认 PATH 里装了 CLI 后重进向导」——「重进向导」对已经站在向导里的人是无效指引；没有重新扫描按钮；自定义 agent 注册面只在注入 `customAgents` 端口时出现（:186-187，纯 vite 环境 null）。

### CC-B5 🟡 M2 项目实例的归属盲区（低频但真）
- 项目内走向导建档 → `character.create` 不带 instanceId → 落库按 COALESCE 归默认沙盒（`character-record.ts:192`）→ 当前会话看得见、**重载项目后消失**（instance-loader 只 load 本实例实体，:215-221）。
- 项目角色正路是名册契约物化（roster-materializer.ts），但**没有名册编辑面**——契约外的用户在项目里建角色必然踩坑。

## 2. 设计原则（4 条）

1. **入口永远可达，面板内部兜住一切状态**：「能不能建」的判定从入口挪进向导；入口只负责打开面板——点「新建角色」必须 100% 有响应。
2. **没有出口的空态是禁止的**：每个空态必须带至少一个可走动作。
3. **禁用必须带原因，永不静默吞点击**（沿用 task_154 已确立的 footer-reason 口径，把它贯彻到人设步）。
4. **归属必须可见**：任何写入都要让用户知道"建到了哪里"。

## 3. 设计方案

### A. 入口层：三入口一口口径，「无条件挂向导」（修 B2）
- `reopen({force:true})` 删掉「bindable 为空就 return」前置（onboarding-host.ts:157-159）：向导**总是挂**；扫描中的等待态、扫描完 0 结果的空态都由扫描步自己呈现（它本来就有「正在等扫描结果…」:1330 逐条推送刷新）。
- 删掉 main-entry.ts:1267-1268 的 navigate 兜底（不再需要）。
- 理由：service 侧检测是逐条广播的，用户点按钮的瞬间 lastState 可能还没收到结果（时序竞态）——入口处一次定生死是竞态温床；挂起来等广播才是正解。

### B. 角色中心：空态 CTA + 子屏常驻钮（修 B1）
- B1-1 空态组件（cards-empty 位置）加主 CTA「＋ 新建角色」：派 DOM 事件（`strat-character-create`，冒泡+composed）→ app 层接 `openCharacterWizard()`——与战场空态同一装配口径（HUD 发事件、组合根接线，battlefield-empty 先例）。
- B1-2 角色中心子屏 topbar 加常驻「＋ 新建角色」按钮（variant=primary 不必，default 即可）：不只空态，任何角色数都有一级入口（与主屏顶栏同款同动作）。
- 空态文案同步改：「尚无角色档案」+ CTA + 一句「也可以回战场点右下角命令行，或按 ⌘K」（多路提示，不绑死单一路径）。

### C. 向导状态机补全（修 B3 + B4）
- **C1 人设步**（B3）：
  - `stepBlockReason()` 把 persona 纳入：人设未配置（无预设且问卷缺题）→ 主按钮 **disabled** + footer-reason 显示「人设还没配好：答完问卷或选一个预设（第 N 个 agent 还差 M 题）」。
  - **新增「用默认模板」按钮**（人设步 footer 左侧，default variant）：一键把该 agent 的人设标为「空=建档时套默认模板」语义（等价跳过问卷），点击后主按钮解锁。why：空人设本就合法，问卷不该是强制门槛；想精心配的用户照旧走问卷/预设。
  - 点击 disabled 按钮时（strat-button 已 disabled 不派点击）——footer-reason 已说明原因，不再需要额外 toast。
- **C2 扫描步 0 结果空态**（B4）：文案改动作化三选：
  - 「重新扫描」按钮 → 重派 detection 命令（core 既有检测口）；
  - 「＋ 添加自定义 agent」入口：`customAgents` 端口存在时显示（Electron 已有）；
  - 「查看 CLI 安装指引」链接 → docs（渲染层开系统浏览器既有能力）；
  - 删除「重进向导」这句无效指引。
- **C3 归属条**（B5 短期）：向导顶部常驻一行「将建到：默认沙盒」；在项目实例里打开时追加说明「项目角色由名册契约管理（.stratix/roster/），这里建的角色归沙盒」；完成后 toast 带归属。项目内名册编辑器 = backlog 另立（不在本轮）。

### D. 明确不做的（防止镀金）
- 不做"跳过向导直接快速建档"的第二套面板——向导内部补状态就够了，两套建档 = 两个真相。
- 不改战场空态/命令行/⌘K 三个入口的位置与样式（它们没问题，问题在点击之后）。
- 不在本轮做项目名册编辑器（挂 backlog）。

### 4.1 实施摘要（2026-11-09 · CC-01 ~ CC-04）

> 每条 V 一句话：落地了什么、落在哪。回归落在

- **V1**（战场空态「新建角色」→ 向导必挂）：入口改成 `reopen({ force: true })` **无条件挂向导**，
  并删掉「挂不起就 `navigate('character')`」的兜底 —— 能不能建由向导的扫描步判定，不再由入口一次定生死（CC-01，`onboarding-host.ts` / `main-entry.ts`）。
- **V2**（顶栏「＋角色」/ ⌘K）：与 V1 收敛到同一条 `openCharacterWizard()`，三个入口口径一致、响应一致（CC-01）。
- **V3**（角色中心空态 CTA）：0 角色时 cards-empty 位置加主 CTA「＋ 新建角色」，
  派 `strat-character-create` 事件，由组合根接成同一条路（CC-01，`character-screen.ts` / `main-entry.ts`）。
- **V4**（角色中心子屏顶栏常驻钮）：子屏 topbar 加常驻「＋ 新建角色」（default 变体），任何角色数都有一级入口（CC-01）。
- **V5**（扫描完 0 可建档）：向导不关，扫描步空态改成**三个动作** —— 重新扫描（派 `strat-onboarding-rescan`，组合根重派既有 detection 命令）·
  ＋添加自定义 agent（`customAgents` 端口存在时）· 查看 CLI 安装指引（外链 docs/AGENT-MATRIX.md）；删掉「重进向导」那句无效指引（CC-02）。

- **V9**（答完问卷）：问卷 / 预设两条路照旧解锁主按钮，本轮作为回归确认保留（CC-02 回归）。
