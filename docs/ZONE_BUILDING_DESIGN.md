# Zone Building System — 设计文档 v1

> **创建时间**: 2026-04-30
> **状态**: 设计阶段
> **目标**: 把 Zone 从抽象矩形变成有叙事感的建筑，Agent 在建筑内部工作

---

## 一、核心概念

**Zone = 一栋建筑，建筑内部是格子间，每个 Agent 一个工位。**

用户画框创建 Zone → 选择功能类型 → 地图上长出一栋建筑 → 分配 Agent → 建筑亮起 → Agent 在格子间里干活。

---

## 二、视觉设计

### 2.1 建筑外观（俯视像素风）

**默认态（未选中）**：
```
┌─────────────────────────────┐
│                             │
│      🏢 数据分析中心         │  ← 屋顶纹理 + 建筑名称
│      👥 5 · 🟢3 🟡1 ⚪1    │  ← Agent 数量和状态汇总
│      ████████░░ 60%         │  ← 整体进度条
│                             │
└─────────────────────────────┘
```

**选中态（屋顶消失，透视内部）**：
```
┌─────────────────────────────┐
│ ┌──────┐ ┌──────┐ ┌──────┐ │
│ │  💻  │ │  📊  │ │  💻  │ │
│ │ 工作中│ │ 空闲 │ │ 工作中│ │  ← 每个 Agent 一个格子间
│ ├──────┤ ├──────┤ │      │ │
│ │  📊  │ │  💻  │ │ 空位 │ │  ← 空位 = 未分配工位
│ │  等待 │ │ 工作中│ │      │ │
│ └──────┘ └──────┘ └──────┘ │
│            🚪               │  ← 建筑入口
└─────────────────────────────┘
```

### 2.2 建筑类型

| Zone 类型 | 建筑名称 | 外墙风格 | 内部装饰 | 格子间特征 |
|-----------|---------|---------|---------|-----------|
| 数据分析 | 数据机房 | 金属质感、散热栅格 | 服务器架、屏幕墙 | 屏幕闪烁 + 数据流动画 |
| 代码开发 | 开发工坊 | 砖墙、管道外露 | 电路板纹理、终端 | 代码瀑布 + 编译动画 |
| 图像生成 | 创意画室 | 大窗户、明亮 | 画架、调色板 | 色彩渲染 + 光晕动画 |
| 内容写作 | 编辑书房 | 木质、书架 | 书籍、台灯 | 墨水流动 + 页面翻动 |
| 通用协调 | 指挥中心 | 全息投影风格 | 大屏、信号灯 | 信号闪烁 + 调度动画 |

### 2.3 Agent 状态动画

| Agent 状态 | 格子间内表现 |
|-----------|-------------|
| 工作中 | 小人伏案/操作 + 格子间亮灯 + 微动动画 |
| 空闲 | 小人坐着/站着 + 格子间灯光柔和 |
| 等待中 | 小人来回走动 + 格子间灯光闪烁 |
| 错误 | 格子间红灯 + 小人举手 + 感叹号 |
| 离线 | 格子间暗灯 + 小人灰色/不可见 |

### 2.4 建筑缩放规则

- 建筑外壳完全匹配 Zone 矩形大小
- 内部格子间数量 = Agent 数量 + 空余工位
- 格子间大小自适应：格子数少 → 格子大，格子数多 → 格子小
- 最小格子间：48×48 像素
- 最大格子间：96×96 像素

## 三、交互流程

### 3.1 创建 Zone

```
1. 用户在空地图上拖拽画框
2. 松手 → 弹出类型选择面板
   [机房] [工坊] [画室] [书房] [指挥中心]
3. 选择类型 → 框内出现建筑（有生长动画）
4. 建筑默认为「空楼」状态（无人、暗灯）
```

### 3.2 分配 Agent

```
1. 从 Agent 列表拖拽 Agent 到建筑上
   或：选中建筑 → 点击「分配 Agent」按钮
2. Agent 进入建筑 → 对应格子间亮灯
3. Agent 开始工作 → 格子间出现工作动画
4. 建筑顶部标签更新（人数 + 状态）
```

### 3.3 查看内部

```
1. 点击/选中建筑 → 屋顶消失动画
2. 内部格子间可见，每个格子间显示 Agent 头像 + 状态
3. 点击某个格子间 → 右侧面板显示该 Agent 的详细信息
4. 点击空白处 → 屋顶恢复
```

### 3.4 首次进入体验

```
1. 用户首次进入 → 地图空旷，只有基础地面纹理
2. 地图中央显示引导提示：「拖拽绘制你的第一个工作区域」
3. 用户画第一个 Zone → 引导选择类型 → 建筑生长
4. 引导分配第一个 Agent → 建筑亮起
5. 引导完成，开始正常使用
```

## 四、技术实现

### 4.1 与现有 Zone 系统的集成方式

**核心决策：建筑是 BaseZone Container 的子对象，不替代 Container。**

```
BaseZone (Phaser.GameObjects.Container)  ← 现有，不改
├── graphics (边框/填充)               ← 现有，建筑模式下隐藏或替换
├── fillGraphics                       ← 现有
├── shadowGraphics                     ← 现有
├── glowGraphics                       ← 现有
├── [NEW] buildingContainer            ← 建筑系统所有视觉元素
│   ├── buildingFoundation             ← 建筑地基
│   ├── roomsContainer                 ← 格子间容器（选中态可见）
│   │   ├── Room[0]                    ← 格子间 0
│   │   ├── Room[1]                    ← 格子间 1
│   │   └── ...                        
│   ├── buildingShell                  ← 外墙 + 屋顶（默认态可见，选中态隐藏）
│   └── buildingLabel                  ← 标签（始终可见）
```

**集成方式**：
- `TaskZone`（`extends BaseZone`）新增一个 `createBuilding(type)` 方法
- 调用后创建 `Building` 对象，作为子对象加入 Container
- 原有的 graphics（边框/填充）在建筑模式下设为不可见
- 所有建筑相关的渲染逻辑封装在 `Building` 类里，不影响 BaseZone 的拖拽/resize/选择逻辑

**好处**：
- 改动最小，不侵入现有 Zone 的交互逻辑
- BaseZone 的 drag/resize/select 完全复用
- 建筑只是视觉层的增强

### 4.2 Zone 之间的连接与路径

**v1 方案：直线移动，不做寻路。**

Agent Transfer（从 Zone A 到 Zone B）的移动方式：
1. 从 A 的格子间移出 → 出现在 A 的门口
2. 直线移动到 B 的门口（忽略障碍物）
3. 进 B 的格子间

**理由**：
- v1 阶段 Zone 数量少（通常 3-10 个），直线移动视觉上够用
- 寻路（A*）增加了复杂度但 v1 看不出差异
- 后续如果 Zone 密集到需要绕路，再加寻路

**数据流连接线**：
- 现有 `ZoneConnectionManager` + `ConnectionRenderer` 已经处理了 Zone 之间的连线
- 建筑模式下连线改为从建筑的「出口」连到另一栋的「入口」（现在是 Zone 中心到中心）
- 这个改动很小，只是端点坐标的调整

### 4.3 数据模型变更

**现有 Zone 表已有字段**（`zone_contexts` + `projects` 联表）：
```sql
-- 现有字段足够了
id, project_id, title, prompt, description, priority, status,
path, present_agent_ids, config (JSON: x/y/width/height/color/opacity/visible)
```

**需要扩展的**：`config` JSON 字段新增两个属性：

```typescript
interface ProjectZoneConfig {
  x: number;
  y: number;
  width: number;
  height: number;
  color?: number;
  opacity?: number;
  visible?: boolean;
  // ↓ 新增
  buildingType?: 'data-center' | 'workshop' | 'studio' | 'library' | 'command';  // 建筑类型
  buildingState?: 'empty' | 'active' | 'busy' | 'full' | 'error';                // 建筑状态（派生，可不存）
}
```

**不需要新建表**。理由：
- 格子间布局是运行时根据 Zone 大小 + Agent 数量计算的，不需要持久化
- Agent 的 Zone 归属已经在 `present_agent_ids` 字段里
- 建筑类型加在 config JSON 里就够了，不需要独立字段

**API 变更**：
- `POST /api/zones` — 请求体新增 `buildingType` 字段
- `PATCH /api/zones/:id` — 支持更新 `buildingType`
- `GET /api/zones/:id` — 响应里包含 `buildingType`
- Agent 分配/取消分配：复用现有 `POST /api/zones/:id/members` 接口

### 4.4 新增模块

```
src/stratix-rts/
├── buildings/
│   ├── Building.ts              # 建筑类（管理外壳+屋顶+格子间+标签）
│   ├── BuildingFactory.ts       # 根据 buildingType 创建 Building
│   ├── BuildingRenderer.ts      # 建筑渲染（外壳 + 屋顶 + 地基）
│   ├── Room.ts                  # 格子间（位置、大小、状态）
│   ├── RoomRenderer.ts          # 格子间渲染（Agent 动画 + 状态图标）
│   ├── BuildingLabel.ts         # 建筑标签（名称 + Agent 数 + 进度）
│   └── types/
│       ├── BuildingType.ts      # 建筑类型枚举 + 配色方案
│       └── BuildingState.ts     # 建筑状态枚举
```

### 4.2 建筑纹理

用现有的 texture-generator 扩展，为每种建筑类型程序化生成：

- **外墙纹理**：每种类型一套（墙壁 + 屋顶 + 门）
- **内部纹理**：地板 + 格子间边框 + 装饰物
- **状态纹理**：亮灯/暗灯/红灯 的格子间变体
- **Agent 动画**：2-3 帧的简单像素动画（伏案、走动、举手）

纹理尺寸：64×64 基础单元，可平铺

### 4.3 渲染层次

```
Depth 0:   地面纹理（已有）
Depth 1:   建筑地基（Zone 区域内的地板变化）
Depth 2:   格子间（选中态可见）
Depth 3:   Agent 动画（选中态可见）
Depth 4:   建筑外墙 + 屋顶（默认态可见，选中态隐藏）
Depth 5:   建筑标签（始终可见）
Depth 6:   连接线 / 数据流（建筑之间）
```

### 4.4 动画系统

| 动画 | 触发 | 实现 |
|------|------|------|
| 建筑生长 | Zone 创建 | scale 0→1 + 烟尘粒子 |
| 屋顶消失 | Zone 选中 | alpha 1→0 + 透明度渐变 |
| 屋顶恢复 | Zone 取消选中 | alpha 0→1 |
| Agent 工作 | Agent 状态变更 | sprite 动画帧切换 |
| 建筑亮灯 | Agent 进驻 | 全局 brightness tween |
| 进度条 | 任务进度更新 | 直接更新 graphic |

## 六、CRUD 完整梳理

### 6.1 Zone CRUD

| 操作 | 现有实现 | 建筑系统补充 |
|------|---------|-------------|
| **Create** | 用户画框 → 创建 Zone 对象 → BaseZone/TaskZone | → 触发建筑生长动画 → 根据类型初始化建筑外壳 → 根据尺寸划分格子间网格 |
| **Read** | 点击 Zone → 高亮边框 → 右侧面板显示信息 | → 选中态：屋顶淡出 → 内部格子间可见 → 每个 Agent 显示状态动画 → 右侧面板展示详情 |
| **Update（resize）** | 部分实现（UnifiedZoneManager 有 spatialIndex update） | → 重新计算格子间布局 → 现有 Agent 按序重分配 → Agent 位置平滑过渡（tween） → 空余工位自动增减 |
| **Update（move）** | 拖拽移动 Zone | → 建筑整体跟随移动（Container 已处理） → 地面装饰在旧位置恢复、新位置清除 |
| **Update（类型变更）** | 暂无 | → 建筑外壳纹理替换 → 内部装饰风格切换 → 过渡动画（闪光/变色） |
| **Delete** | `zones.delete(zoneId)` + spatialIndex 移除 | → 建筑倒塌动画（scale 1→0） → 内部 Agent 弹出为自由 Agent → 进行中任务标记「中断」 → 建筑对象归还对象池 → 地面装饰恢复 |

### 6.2 Agent CRUD

| 操作 | 现有实现 | 建筑系统补充 |
|------|---------|-------------|
| **Create** | `addAgentSprite()` → 生成像素小人 | → 检查是否有 Zone 分配 → 有则放入对应格子间（进门动画）→ 无则在地图上自由显示 |
| **Read** | Agent sprite 可见 + 选中查看详情 | → 在格子间内：显示 Agent 缩略图 + 状态图标 + 工作动画 → 自由态：原有像素小人 |
| **Update（状态）** | `updateAgentPosition()` + 状态属性 | → 状态变更触发格子间内动画切换：工作中/空闲/等待/错误各有不同表现 |
| **Update（位置）** | `updateAgentPosition()` | → 在格子间内：位置由格子间决定，不响应自由移动 → 自由态：正常移动 |
| **Delete** | `removeAgent()` → sprite destroy | → 格子间清空（变回空工位状态） → 如果是最后一个 Agent → 建筑进入「空楼」暗灯状态 |
| **Assign（进 Zone）** | Agent 关联 Zone | → 自由 Agent → 进门动画 → 分配到空余格子间 → 格子间亮灯 |
| **Unassign（出 Zone）** | 取消关联 | → 出门动画 → 格子间清空 → Agent 变回自由态（在建筑门口出现） |
| **Transfer（Zone A → B）** | 暂无 | → A 的格子间清空 → Agent 出 A 门 → 地图上短暂移动 → 进 B 门 → 分配 B 的格子间 |

### 6.3 Agent 数量边界

| 场景 | 处理方式 |
|------|----------|
| Agent 数 < 格子间数 | 多余格子间显示为「空工位」（暗灯） |
| Agent 数 = 格子间数 | 刚好满员，所有格子间亮灯 |
| Agent 数 > 格子间数 | 自动缩小格子间尺寸以容纳更多，最小 32×32；若仍不够则拒绝分配并提示「区域已满」 |
| Zone 内无 Agent | 建筑进入「空楼」状态：整体暗灯 + 标签显示「待分配」 |

### 6.4 非 Zone 区域背景

**现有能力**：
- `GroundDecorationSystem`：随机装饰物（草/石/树/花/水/云），密度 6%
- `ThemeManager`：4 个主题（fantasy / cartoon / cyberpunk / nature），各有 10 种纹理
- `GroundDecorationSystem`：地表平铺（ground_base TileSprite）

**种子策略（确定性生成）**：
- 当前问题：装饰物用 `Math.random()` 生成，每次刷新布局不同
- 改进：使用固定种子伪随机，保证同设备同项目每次打开地图一致

```typescript
// 两层种子
const mapSeed = deviceId;   // 大地图地形：由设备决定，同一台设备看到同一张地形
const zoneSeed = zone.id;   // Zone 内部：由 Zone ID 决定，每个 Zone 内部布局不同
```

| 层级 | 种子来源 | 决定什么 |
|------|---------|----------
| 大地图 | Device ID | 地面装饰物分布（树/石/花/水/云的位置）|
| Zone 内部 | Zone ID | 格子间排列细节、内部微装饰 |

**设计意图**：
- 大地图是「物理世界」，由设备决定，同一台机器看到的永远是同一片地形
- Zone 是「建筑」，由项目决定，每个 Zone 的内部布局独特
- 不需要持久化装饰物坐标，只需要存种子，运行时计算

**与建筑系统的协调**：
- Zone 区域内：地面纹理替换为建筑地板，不显示自然装饰物
- Zone 区域外：保持现有自然地面 + 基于种子的确定性装饰
- Zone 创建时：清除 Zone 区域内的自然装饰物（按坐标排除）
- Zone 删除时：恢复自然地面纹理（种子不变，自动还原）
- 首次进入（无 Zone）：整张地图是自然地面 + 装饰物，引导用户画第一个 Zone

## 七、边界情况处理

### 6.1 Zone 大小变更

1. 监听 Zone resize 事件
2. 重新计算格子间布局（列数 × 行数）
3. 现有 Agent 按顺序重新分配到新格子间
4. Agent 位置平滑过渡动画（tween 从旧位置滑到新位置）
5. 空余工位自动出现/消失

### 6.2 Zone 删除

1. 建筑「倒塌」动画（scale 1→0 + 碎片粒子）
2. 内部 Agent 被弹出 → 变成自由 Agent（回到地图上）
3. 进行中的任务标记为「中断」状态
4. 建筑对象从渲染列表移除，归还对象池

### 6.3 大量 Zone 性能优化（LOD 分层）

| 视口状态 | 渲染策略 | 渲染内容 |
|---------|---------|----------
| 视口内 + 选中 | LOD 0 完整渲染 | 格子间 + Agent 动画 + 内部装饰 |
| 视口内 + 未选中 | LOD 1 标准渲染 | 屋顶 + 标签 + 简单状态指示 |
| 视口边缘 | LOD 2 简化渲染 | 缩小图标 + 数字标签 |
| 视口外 | LOD 3 不渲染 | 只保留数据，无显示对象 |

**具体优化手段**：
- **对象池**：格子间、Agent 动画用 Phaser Group 对象池，避免频繁创建/销毁
- **脏标记**：只有状态变化时才更新渲染，不做逐帧全量重绘
- **纹理复用**：所有同类型建筑共用同一套纹理，不按建筑实例复制
- **视口裁剪**：复用现有 RenderModeSystem 的 LOD 逻辑
- **更新节流**：LOD 2/3 的建筑不跑 update tick，只在进入视口时刷新一次

## 七、设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 视角 | 俯视图 | 与现有 RTS 场景一致，实现简单 |
| 风格 | 像素风 | 与现有纹理生成工具一致，64×64 可平铺 |
| 建筑布局 | Zone = 一栋建筑 | 比多栋建筑简单，不用处理建筑间连接 |
| 内部结构 | 格子间 | 每个 Agent 一个工位，直观清晰 |
| Agent 可见性 | 默认在建筑内，选中时可见 | 减少默认态视觉噪声 |
| 建筑大小 | 等比匹配 Zone | 不用额外处理大小规则 |
| 建筑间连接 | v3 再做 | v1/v2 先让单建筑跑通 |
| Zone 变更 | 重建内部 + Agent 重定位 | 格子间是 Zone 的派生物，不是独立实体 |
| Zone 删除 | 建筑关联删除 | Agent 弹出为自由状态 |
| 建筑/Zone 集成 | 建筑作为 BaseZone Container 的子对象 | 改动最小，不侵入现有 drag/resize/select 逻辑 |
| 数据模型 | 扩展现有 config JSON，不建新表 | buildingType 加在 config 里，格子间运行时计算 |
| Zone 间移动 | v1 直线移动，不做寻路 | Zone 数量少时直线够用 |
| 种子策略 | Device ID 做地图种子，Zone ID 做内部种子 | 不需要持久化装饰物坐标 |
